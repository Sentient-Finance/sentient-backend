> Execute this checklist **immediately** upon discovering credentials leaked in chat, logs, or any insecure channel.

## Rotation Checklist – Step by Step

### 1. GitHub PAT (Personal Access Token)

- [ ] Go to <https://github.com/settings/tokens>
- [ ] Find the leaked token → **Delete**
- [ ] Create a new token: **Fine-grained** (preferred) or Classic
  - Minimum scopes: `Contents: Read & Write`, `Pull requests: Read & Write`, `Issues: Read & Write`
- [ ] Update the new token wherever it is used (local git credential, CI secret, etc.)
- [ ] Verify: `git ls-remote origin` with the new token → OK

### 2. EVM Deploy Wallet Private Key

> **Highest priority** – a leaked key means funds can be drained immediately.

- [ ] **Immediately**: Create a new wallet

  ```bash
  # Using Foundry
  cast wallet new

  # Or generate via ethers.js / wagmi CLI
  ```

- [ ] Transfer all native tokens (ETH, BASE, ARB) to the new wallet
- [ ] Transfer all ERC-20 tokens to the new wallet
- [ ] Revoke token approvals on the old wallet (use revoke.cash or Etherscan)
- [ ] Update `DEPLOY_PRIVATE_KEY` in `.env` and GitHub Secrets
- [ ] Update the deployer address in infra/config if there is an allowlist

### 3. OpenClaw Webhook Token

- [ ] Go to OpenClaw dashboard → Webhook settings → **Regenerate token**
- [ ] Copy the new token

### 4. Update GitHub Actions Secrets

> At: GitHub repo → **Settings** → **Secrets and variables** → **Actions**

- [ ] Update `OPENCLAW_HOOK_TOKEN` → new token from step 3
- [ ] Update `OPENCLAW_HOOK_URL` → if the URL changed
- [ ] Update `DEPLOY_PRIVATE_KEY` → new wallet key from step 2
- [ ] Update any PAT-based secrets → new PAT from step 1

### 5. Update Runtime `.env`

- [ ] Open `.env` on the running server/VPS
- [ ] Replace old values → new values for all rotated secrets
- [ ] Restart services:

  ```bash
  docker compose down && docker compose up -d
  # or
  systemctl restart sentient-api sentient-worker sentient-indexer
  ```

### 6. Confirm Old Tokens Are Revoked

- [ ] Test old GitHub PAT:

  ```bash
  curl -H "Authorization: Bearer <OLD_TOKEN>" https://api.github.com/user
  # Expect: 401 Unauthorized
  ```

- [ ] Test old OpenClaw token:

  ```bash
  curl -H "Authorization: Bearer <OLD_TOKEN>" "$OPENCLAW_HOOK_URL"
  # Expect: 401 Unauthorized
  ```

### 7. Verify Workflow Passes

- [ ] Trigger `openclaw-bridge.yml` manually:
  - GitHub repo → **Actions** → **OpenClaw GitHub Bridge** → **Run workflow**
- [ ] Job completes **green** → new token is working ✅

## Verification Checklist (Done When)

- [ ] Old token returns `401` when tested manually
- [ ] `openclaw-bridge.yml` workflow_dispatch passes
- [ ] No secrets hardcoded in code (run scan below)
- [ ] This checklist file has been committed to the repo

### Secret Scan (run before committing)

```bash
# Scan the entire repo for patterns that look like secrets
git log --all --full-history -- '*.env' | head -20
grep -r "ghp_\|github_pat_\|xox\|sk-\|0x[0-9a-fA-F]\{64\}" . \
  --include="*.py" --include="*.yml" --include="*.yaml" \
  --include="*.json" --include="*.toml" \
  --exclude-dir=".git"
```

If grep returns results → review immediately; you may need `git filter-repo` to purge from history.

## Prevention

- Never paste secrets into chat, PR descriptions, issues, or commit messages
- Always use `.env` (gitignored) for local, GitHub Secrets for CI
- Enable [GitHub Secret Scanning](https://docs.github.com/en/code-security/secret-scanning/about-secret-scanning) for the repo
- Consider using [git-secrets](https://github.com/awslabs/git-secrets) or [gitleaks](https://github.com/gitleaks/gitleaks) as a pre-commit hook
- Use Fine-grained PATs with an expiry date instead of classic PATs that never expire
